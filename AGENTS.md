# AGENTS

- Agency (whitelabel) data lives in `agency_*` tables guarded by `is_agency_owner()`/`is_staff()`; only staff can set `clients.is_agency` — prevents self-promotion.
- Agency weekly fee math runs in `get_agency_week_summary` (Friday–Thursday week); AD SCALE share is charged on the agency's total spend — keeps billing server-side and consistent.
- Agencies never see Meta apps/tokens/BMs; they read only their own assigned ad accounts via existing client RLS — protects infrastructure secrecy.
- Agency demo data (demo.agencia@adscalehub.com and its real end-client logins demo.loja@/demo.infoprodutor@adscalehub.com) is simulated client-side in `src/components/agency/agency-accounts.ts` and `agency-demo-client.ts`; ClientDashboard swaps it in and skips DB writes for those logins; never seed fake rows into meta_ad_accounts — keeps admin data clean.
- Agency support tickets live in `agency_support_tasks` (same pendente/em_andamento/concluida/cancelada flow as internal_tasks), scoped by `is_agency_owner()` — agencies never see AD SCALE's internal tasks.
- Agency end-client signup reuses AgencySignup at /cadastro; the agency is resolved from ?agencia=<slug> or the custom domain via get_agency_branding(), and client-signup links the new real clients row in agency_sub_clients.client_id — sub-clients log into the same ClientDashboard as AD SCALE clients.
- Sub-client support_requests are auto-tagged with agency_client_id by trigger and stay hidden from AD SCALE inboxes until the agency forwards them via `agency_handle_support_request()` — agency triages first, AD SCALE only sees forwarded requests.
- Agencies open a real sub-client's full ClientDashboard at /agencia/cliente/:clientId (read-only, like admin view) via `agency_visible_client_ids()`/`agency_visible_ad_account_ids()` RLS; agency-assigned accounts reach the sub-client dashboard through `get_agency_linked_accounts()` — one dashboard for all end clients.
- Sub-client dashboards take the agency's brand (name, logo, color, title, footer, support chat) (plus browser-tab favicon/title via `applyHeadBranding`) from `get_client_agency_branding()` via `useClientAgencyBranding`, and on /login and /cadastro via `get_agency_branding()`; AD SCALE branding shows only when it returns nothing — agency end clients never see AD SCALE.
- Agency collaborators live in `agency_members` (created only by the `agency-members` edge function, owner-only) with per-section `permissions`; RLS uses `agency_can()`/`agency_can_any()` so section limits are enforced server-side, not just hidden in the UI.
- An agency's own support WhatsApp (`agency_settings.support_whatsapp`) replaces AD SCALE's number for its end clients in the chat, payment and overdue buttons — agency clients never reach AD SCALE directly.
- Weekly goal rates for AD SCALE clients come only from `tiersForClient()` in `src/lib/commission-tiers.ts` (custom goals win, otherwise global goals adjusted to the loyalty base %) — dashboard, admin cards and auto-commissions must stay in sync.
- Agency logo/favicon uploads are resized in the browser (`src/lib/image-resize.ts`) and stored as PNG data URLs in `agency_settings` — the workspace blocks public storage buckets, and anonymous /login and /cadastro must still load them.
- Agency custom domains follow request → AD SCALE connects the domain in Lovable and pastes the A/TXT values (`domain_*` columns, staff-only via `agency_settings_domain_guard`) → agency creates DNS → staff marks active; no Primary domain may be set on the project or agency domains would redirect away.
